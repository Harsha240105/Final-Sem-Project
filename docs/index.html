🎯

What is Web3Connect?

Web3Connect is a Blockchain-Enabled Virtual Campus Platform that lets teachers create communities, assign tasks, and issue NFT certificates minted on the Polygon Amoy testnet. Students earn soulbound (non-transferable) ERC-721 tokens as proof of their achievements.

❓

Problem It Solves

  • Centralized certificates are vulnerable to fraud and tampering
  • Students don't truly own their credentials
  • Manual verification is slow and expensive
  • No built-in social/collaborative learning tools
  • No verifiable teacher credentialing system
✅

Key Features

  • Wallet-based login (MetaMask + SIWE)
  • Teacher verification with document upload & admin approval
  • Community management with tasks & collaborations
  • Automated NFT certificate minting on task completion
  • Real-time messaging (DM, group chat, server channels)
  • Social graph: follow/unfollow, discover, leaderboard
  • Admin panel for platform governance
  • AI-powered OCR verification for student IDs

API Architecture

RESTful APIs and Socket.IO real-time communication — how they work.

REST API

All API endpoints follow REST principles. They are prefixed with /api and use standard HTTP methods (GET, POST, PUT, PATCH, DELETE). Authentication is done via Bearer <JWT> in the Authorization header.

How it works: The frontend Axios client (services/api.js) makes HTTP requests. The Express server routes them to controllers which execute business logic, interact with MongoDB (via Mongoose), and return JSON responses. Middleware handles auth, CORS, rate limiting, and validation.

Socket.IO (Real-Time)

Socket.IO enables bidirectional real-time communication. It's used for:

  • Direct messaging with typing indicators & read receipts
  • Community/Task room-based chat
  • Server channel messaging (Discord-like)
  • WebRTC signaling for voice/video/screen-share
  • Online/offline presence detection
  • Notifications (new task, certificate issued, etc.)

Rate limited: 10 messages/sec per socket. JWT-authenticated connections.

Student Structure

Everything a student can do on the platform, explained step by step.

🎓 Student Journey — Step by Step

1. Connect Wallet
Student connects their MetaMask wallet. The platform detects Polygon Amoy network. A JWT token is issued after wallet signature verification.
2. Complete Onboarding / Verification
Student submits college ID for AI-powered OCR verification. Tesseract.js extracts name, college, registration number. Matching engine compares against form data (85% threshold). If approved, student gains full access.
3. Browse & Join Communities
Student discovers communities on the Communities page. Can join any public community created by verified teachers. Each community has its own tasks, members, and chat.
4. View & Complete Tasks
Teacher posts tasks within communities. Student views tasks assigned to them, submits solutions (text + file uploads), and marks tasks as complete.
5. Earn NFT Certificates
When all tasks in a community are completed, the teacher triggers certificate issuance. The system generates a styled PNG certificate, uploads it to IPFS via Pinata, mints an ERC-721 soulbound NFT on Polygon Amoy, and stores the record.
6. View Certificates & Profile
Student views all earned NFTs in My Certificates page. Certificate details include IPFS metadata, transaction hash, and token ID. Profile shows follower/following stats, community memberships, and certificate gallery.
7. Social Features
Follow/unfollow other students and teachers. Discover users. View connections graph. Send direct messages. Join server channels. Participate in leaderboards.

Teacher Structure

How teachers join, get verified, create communities, and issue certificates.

👨‍🏫 Teacher Journey — Step by Step

1. Register as Teacher
Teacher connects wallet and registers with role "teacher". Profile stored in both User and Teacher collections.
2. Submit Verification Documents
Teacher submits: full name, employee ID, college email, college name, college ID image, signature image (via SignaturePad). Documents stored on server via Multer.
3. Wait for Admin Approval
Status set to pending_approval. Admin reviews documents in Admin Panel and approves/rejects. Teacher receives email/SMS notification.
4. Create Communities
Approved teachers create communities with name, description, image, and college name. They become the community creator with full management rights.
5. Create & Manage Tasks
Teachers post tasks within communities: title, description, attachments. Tasks can require file submissions. Teachers track completion status per student.
6. Issue NFT Certificates
When students complete all tasks, teachers trigger certificate minting. The pipeline: generate certificate image (node-canvas) → upload to IPFS (Pinata) → mint NFT on Polygon Amoy (ethers.js) → save Certificate document → notify student.
7. Manage Community & Collaborate
Teachers can assign Community Managers, remove members, moderate comments, manage collaborations, and use community chat.

Admin Structure

Platform governance and oversight capabilities.

🛡️ Admin Journey — Step by Step

1. Admin Setup
First admin created via /admin/setup page using ADMIN_SECRET env variable. Subsequent admins created by existing admins.
2. Dashboard Overview
Admin panel shows total counts: students, teachers (pending/approved/rejected), communities, tasks, certificates minted, platform stats.
3. Teacher Approval Queue
Admin reviews pending teacher applications. Views uploaded documents (college ID, signature). Can approve (enables community creation) or reject (soft reject, allows resubmit).
4. Platform Management
Admin can view/approve/reject students, manage users, view platform statistics, monitor blockchain configuration and wallet balance.
5. Blockchain Diagnostics
Admin can run blockchain diagnostics: check contract deployment, verify signer wallet balance, validate network configuration, retry failed certificate mints.

Blockchain Integration

Smart contract, NFT minting pipeline, IPFS storage, and wallet integration explained.

📜

Smart Contract: CertificateNFT

Deployed on Polygon Amoy Testnet (Chain ID: 80002). ERC-721URIStorage with OpenZeppelin's Ownable pattern. Soulbound per ERC-5192.

// Key contract features: contract CertificateNFT is ERC721URIStorage, Ownable { // Transfers permanently disabled (soulbound) function mintCertificate(address student, string memory tokenURI) ... function totalSupply() ... // Counter function locked(uint256) ... // Always true }
🔧

NFT Minting Pipeline (6 Steps)

1. Certificate Image Generation
node-canvas renders HD PNG (3200x2200) with student name, community, QR code
2. IPFS Upload (Image)
Pinata pinFileToIPFS uploads PNG → returns IPFS CID + HTTPS gateway URL
3. Metadata Creation
ERC-721 metadata JSON with name, description, image URI, attributes (student, community, college, date, network)
4. IPFS Upload (Metadata)
Pinata pinJSONToIPFS uploads metadata → returns metadata URI
5. Smart Contract Mint
ethers.js calls mintCertificate(studentWallet, metadataURI) with gas estimation + 20% buffer
6. Database Persist
Certificate document created with tokenId, txHash, IPFS URIs, status = confirmed

🔌 Wallet Integration

Users connect via MetaMask, Coinbase Wallet, or WalletConnect. The frontend uses Wagmi 3.6 + Viem 2.48 for React hooks. Multiple auth methods: direct wallet login, SIWE (Sign-In With Ethereum) with nonce, and traditional email/password fallback. Wallet addresses are validated with regex /^0x[a-fA-F0-9]{40}$/ and stored in lowercase.

Security Layers

How the platform keeps data safe.

Authentication

  • JWT tokens with 24h-7d expiry
  • Wallet signature verification (EIP-1193)
  • SIWE (EIP-4361) structured messages
  • bcrypt password hashing (legacy)
  • Token stored in localStorage + Bearer header

API Security

  • Helmet.js HTTP security headers
  • CORS restricted to allowed origins
  • Rate limiting: 100/min global, 20/15min auth
  • express-validator input sanitization
  • Multer file type/size validation (5MB)

Blockchain Security

  • Private key server-side only (never exposed)
  • Smart contract ownership check
  • Gas estimation with buffer (anti-revert)
  • Duplicate mint idempotency checks
  • Input validation (address format, URI format)
